# scripts/

Nothing here runs in the request path. Who runs each one:

| Script | Runs from | What it does |
|---|---|---|
| `check_colors.py` | CI (`.github/workflows/ci.yml`), `tests/test_color_lint.py` | fails a theme-unsafe literal text colour in the templates |
| `check_silent_handlers.py` | CI, `tests/test_silent_handler_lint.py` | fails a bare `except:` or a swallowed database write |
| `check_timeouts.py` | `tests/test_resiliency.py` | fails an outbound HTTP call with no `timeout=` |
| `check_email_tokens.py` | `tests/test_email_audit_fixes.py` | ratchet on literal colours in email HTML (`emails.BRAND` is the source) |
| `check_owner_copy.py` | `tests/test_owner_copy_lint.py` | ratchet on the banned owner-copy labels (NS1 V7 / NS3 R9: "value delivered", "optimized", "Monthly savings" over a gap, band words as confidence …) in templates, `public/`, Swift and the email/notify modules |
| `check_pin_pepper.py` | by hand — `docs/ops/PIN_PEPPER_RUNBOOK.md` | reports whether `CAVNAR_PIN_PEPPER` is set and which version PINs carry |
| `unlock_login.py` | by hand, break-glass, in the container (`railway ssh`) — `docs/ops/RECOVERY.md` → *Locked out of the console* | clears one login's sign-in lockout — the account lock and every per-address lock (`security.clear_account_lock`) — and records it in `admin_events`; `--dry-run` shows the lock and changes nothing. Touches no password, session or two-factor |
| `refresh_seasons.py` | daily on GitHub Actions (`.github/workflows/refresh-seasons.yml`, 19:30 UTC; also run from the Actions tab or by hand) — never the app or the scheduler. A changed file is checked (`tests/test_event_fix2_w5.py`), committed and pushed, and that deploy loads it; a source it can't read turns the run red | re-reads each team's published schedule and merges it into `event_intel/seasons/*.json`: ids kept, moved dates and starts and finals updated, new games added, TV only where the file has none, nothing deleted (a game the source dropped is listed to check); dry run by default, `--write` to save, then commit and push |
| `repo_inventory.py` | by hand, when a doc needs a number | tables, routes by blueprint, job claim keys, model call sites, test count — from the code (its route count boots the app in a subprocess against a scratch volume) |
| `build_contract_pdf.py` | by hand — `pricing.py` docstring | renders `docs/contracts/Cavnar-AI-Service-Agreement.pdf` from `pricing.TIERS` |
| `docusign_create_template.py` | one-off (built the live DocuSign template, Sep 7 2026) | creates the DocuSign template from that PDF |
| `seed_review_account.py` | `admin_routes.py` (`/admin/seed-review-account`), `docs/app-store-submission.md` | the App Store reviewer's demo account |
| `seed_simple_ejs_reviews.py` | one-off, kept for the record | the seed used for Simple EJ's review history |
| `crew_floors_on_at_once.py` | by hand on production (railway ssh), once per restaurant whose floors were set before 10/10/26 as a count of different people (Simple EJ's) | reads each staffing floor as people on at once (the unit every floor is held in since the schedule fix round, contract #2) and lowers a role family's floors on a shift only where they add up past what its own usual night holds on at once (`crew_matrix.floors_on_at_once`); never raises one; dry run unless `--apply`, which also restates any Crew hold on the changed shifts |
| `staffing_requirements_report.py` | by hand on production (railway ssh), read-only, after the scheduler audit's G2 round deploys | one restaurant's usual crew at its first published Cavnar week against now with each slot's provenance (a Cavnar-era drop held back for want of outcome evidence — LEARNING-5), its labor standards at the rush, next week's work-driven numbers beside the usual crew, the backtested forecast's choice and the stored one-more-person estimates; writes and sends nothing |
| `bar_sales_repair.py` | by hand on production (railway ssh), once after the bar fix round (barfix-1015 W3) deploys, per RPOWER restaurant | the Bar's sales side made right: `--catalog` reads the POS's sales catalog (RPOWER, read-only), each archived night is derived net of its check discounts (`bar.sales.repair_nights`), and a night with net sales but no department dollars (Simple EJ's 9/27/26) is given them from the archive where they add up to its net (`dsr.backfill.repair_department_metrics`; `--archive` stores the night again first). Dry run unless `--apply`; idempotent; sends nothing |
| `bar_load_recipe_cards.py` | by hand on production (railway ssh), after the bar fix round (barfix-1015 W6b) deploys, per bar with recipe cards (Simple EJ's: `--rid 5`) | a bar's recipe cards loaded as SUGGESTED cocktail specs (`bar.variance.load_recipe_cards` → `bar_drink_specs`): each alcoholic ingredient in ounces on its POS button against the bought product its name matches; counted in bought vs rung only once the account holder confirms. Dry run unless `--apply`; idempotent (never touches a confirmed row); sends nothing |
| `render_glows.py` | by hand, after changing a glow's spec (bump its `-vN`) | the dashboard's glows as error-diffused PNGs in `static/img/glow/` — never CSS gradients (DESIGN_SYSTEM §1, No banding, no grain). Writes files only |
| `backoffice_import.py` | by hand on production (railway ssh, the file on stdin with `--file -`), per restaurant on Back Office (Simple EJ's: `--rid 5`), whenever the owner exports a new Invoices By Vendor PDF or Chart of Accounts CSV, or prints one invoice's Edit Invoice page to PDF, or the recipe book is read again from Back Office (JSON, `back_office_recipes.json`) | the file read into `backoffice_ap` (accounts, invoices, an invoice's lines): Food Cost's food bought vs sold and the Bar's alcohol bought outside Fintech. Dry run unless `--apply`; a file already read is a duplicate; sends nothing |

| `load_checklists.py` | by hand on production (railway ssh), after a client's `docs/clients/<client>/checklists.json` changes | loads its sheets onto that restaurant's task sheets (`task_sheets.py`) — each on its job and shift, made when missing, with its title, sign-off, sections and critical lines; dry run unless `--apply`, idempotent across a job's sheets (until 10/15/26 it wrote the flat `task_templates` list task sheets replaced on 9/30/26) |
| `loadtest_staff_signin.py` | by hand | load test for the staff PIN sign-in |

| `invoice_model_eval.py` | by hand, before moving the invoice read (`invoice_extract`) off production's Opus (AI cost audit 10/7/26 #86) | replays a folder of invoice photos / PDFs (the files are not stored — each one's sha256 finds its `invoice_imports` row) on candidate routes (default `default`, `T4:low`, `T4:medium`, `T3:medium`) and scores each against the owner's applied lines (`applied_json`, `by: owner`): confirmed lines read right after `invoices.propose`, the printed total, the qty × price arithmetic, the lines-vs-total check, tokens, seconds and cost per invoice. Plan and cost estimate only unless `--live`; calls metered as `invoice_model_eval`; nothing saved |

Each (archetype, arm) in its own process and throwaway database, no provider key, sockets refused; nothing saved anywhere else |
| `schedule_solver_bench.py` | by hand, before changing the solver-first draft or its default (scheduler audit 10/10/26 RM-21) | the solver-first draft (`schedule_cpsat.solver_draft`) against the v0 code draft and the carry-forward on synthetic 60/150/250-person restaurants (`synthetic()`), each through the repair loop's hard stages and judged by the rule sweep and Shift Quality: draft seconds, hard breaches, unmanaged minutes, quality, labor dollars, overtime, unfilled. A throwaway database; no model; nothing saved |
| `schedule_model_eval.py` | by hand, before changing the schedule's model, its effort or its prompt (schedule audit 10/3/26 PR-31) | replays stored weeks (`schedule_model_calls`, every schedule call's full input and answer) across model × effort × prompt variant (`stored`, `rerender` — today's prompt from the stored arguments — or a `module:function` transform) and scores each week: hard breaches and manager minutes before and after the backstops, full-timers under minimum, rows the backstops change, Shift Quality, what the week does not meet, tokens, seconds and cost per completed week. Plan and cost estimate only unless `--live`; the stored production answers are always scored, free; nothing saved |
